# Личная CRM

Приложение для ведения контактов людей, которых знаешь лично: кто это, откуда знакомы, телефон, почта и заметки после разговоров. Идея и границы продукта — в `specs/01-продуктовая-идея.md`.

## Что умеет

- Список контактов по 50 на странице, новые сверху. Переключатель страниц — над списком и под ним, номер страницы виден в адресе: ссылку на страницу можно открыть в другом браузере
- Поиск по имени среди всех контактов: без учёта регистра, «е» и «ё» считаются одной буквой, слова можно вводить в любом порядке. Если найдено больше 50, найденные тоже делятся на страницы
- «Все контакты» в карточке, на «Добавить контакт» и на «Пора связаться» возвращает на ту страницу списка и с тем поиском, откуда вы пришли
- Добавление контакта: имя (обязательно), кто это, откуда знакомы, телефон, почта, как часто общаться
- Карточка контакта с лентой заметок: каждая заметка сохраняется с датой, новые сверху
- Редактирование контакта
- Удаление контакта: кнопка внизу страницы редактирования, с вопросом «Точно удалить?». Контакт удаляется вместе со всеми заметками и безвозвратно: корзины нет
- «Как часто общаться»: в форме контакта можно выбрать «Раз в неделю», «Раз в месяц», «Раз в квартал», «Раз в год» или оставить «Не задано». Выбранная частота видна в карточке
- Страница «Пора связаться»: люди, с которыми вы не общались дольше выбранного срока, самые просроченные сверху. Ссылка на неё — в шапке главной, рядом число таких людей

- Страница «Группы» (ссылка в шапке главной): свои группы, например «Семья», «Друзья», «Теннис». Группы идут по алфавиту, у каждой видно число контактов. Группу можно создать, переименовать и удалить; при удалении люди остаются в контактах, только без этой группы. Нажатие на название группы открывает главную с людьми этой группы
- Выбор группы на главной: под поиском ряд меток «Все» и группы. Выбрали группу — в списке только её люди; поиск, страницы и подпись работают внутри группы («В группе: 12 контактов»), а сама группа сохраняется в адресе. Группу, которой нет, адрес не ломает: показываются все контакты
- Группы человека видны маленькими метками в строке списка на главной (перед «кто это · откуда знакомы») и на странице «Пора связаться» (после частоты и даты последней заметки)
- Группы в карточке контакта: первая строка «Группы» — метки с крестиком и кнопка «+ группа». Крестик сразу убирает человека из группы (сама группа остаётся). В «+ группа» можно выбрать готовую группу или вписать название: новое создаёт группу, существующее (в любом регистре) просто добавляет человека в неё

Отдельные заметки удалить нельзя — это сознательное решение.

### Как считается «Пора связаться»

- Общение — это заметка в карточке. Срок считается от последней заметки, каждая новая заметка начинает его заново
- Если заметок нет — от дня, когда задали частоту. Новый контакт с частотой — от дня добавления
- Если частоту поменяли на другую — заново от дня смены. Сохранение формы без смены частоты срок не трогает
- Неделя — 7 дней; месяц, квартал и год — по календарю: от 15 января до 15 февраля, 15 апреля и 15 января следующего года. От 31 января месяц заканчивается в последний день февраля
- Человек появляется на странице в день, когда срок наступил, с надписью «пора сегодня»; дальше — «просрочено на N дней»
- Дни считаются по московскому времени

## Что нужно на компьютере

- [Node.js](https://nodejs.org) 20.12 или новее
- [pnpm](https://pnpm.io)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает база данных

## Первый запуск

1. Создайте файл с настройками и заполните в нём значения:

   ```bash
   cp .env.example .env
   ```

   Имена переменных уже есть в `.env.example`. Пароль придумайте любой, порт базы — `5433`. `DATABASE_URL` — это строка подключения целиком: `postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@localhost:5433/ИМЯ_БАЗЫ`.

2. Запустите базу данных:

   ```bash
   docker compose up -d
   ```

3. Установите зависимости и создайте таблицы:

   ```bash
   pnpm install
   pnpm db:migrate
   ```

4. Запустите приложение:

   ```bash
   pnpm dev
   ```

5. Откройте в браузере <http://localhost:3001>.

## Обычный запуск

Когда всё уже настроено, достаточно двух команд:

```bash
docker compose up -d
pnpm dev
```

Остановить приложение — `Ctrl+C` в терминале. Остановить базу — `docker compose stop` (данные сохраняются).

`pnpm dev` — режим разработки: удобен, пока приложение меняется, но страницы открываются медленнее. Чтобы пользоваться приложением на полной скорости:

```bash
pnpm build
pnpm start
```

После изменений в коде `pnpm build` нужно выполнить заново.

## Тестовые данные

```bash
pnpm db:seed
```

Команда добавляет 1000 выдуманных контактов и заметки к ним. Она работает только на пустой базе: если в базе уже есть хотя бы один контакт, команда ничего не меняет и сообщает об этом. Телефоны начинаются с несуществующего кода `000`, почта — на домене `example.com`, так что случайно позвонить или написать реальному человеку не получится.

## Тесты

```bash
docker compose up -d
pnpm test
```

Нужна запущенная база и Node.js 22.12 или новее. Тесты работают в отдельной базе рядом с рабочей — её имя то же, но с `_test` на конце (например, `personal_crm_test`). Они сами создают эту базу и обновляют в ней таблицы, а ваши контакты не трогают. Если база не запущена, тесты сразу скажут: «Start it with `docker compose up -d`».

### Сквозные тесты (e2e)

Настоящий браузер проходит главный сценарий так же, как человек: открывает список, добавляет контакт, находит его поиском, пишет заметку, обновляет страницу и открывает тот же адрес в другом окне без общих данных.

Один раз после установки зависимостей скачайте браузер для тестов:

```bash
pnpm exec playwright install chromium
```

Запуск:

```bash
docker compose up -d
pnpm test:e2e
```

Команда сама собирает приложение (около минуты) и запускает его на порту 3002 со своей базой — имя с `_e2e` на конце (например, `personal_crm_e2e`). Перед каждым тестом эта база очищается; рабочая база и запущенный `pnpm dev` не затрагиваются. Если тест упал, отчёт со скриншотом и записью шагов откроет `pnpm exec playwright show-report`.

## Как проверить руками

1. Откройте <http://localhost:3001> — виден список контактов, над ним подпись: «Всего: N контактов» или, если контактов больше 50, «Показаны 1–50 из N».
2. Нажмите «Добавить контакт», заполните имя, нажмите «Добавить контакт» — новый контакт появился первым в списке.
3. Введите его имя в поиск — список сузился до него. Откройте карточку.
4. Напишите заметку, нажмите «Сохранить заметку» — она появилась в ленте с датой. Обновите страницу — заметка на месте.
5. Откройте тот же адрес в другом браузере — там те же контакты и та же заметка.
6. Откройте карточку контакта (лучше тестового), нажмите «Редактировать», внизу страницы — «Удалить контакт». Появится вопрос с именем и числом заметок; «Отмена» ничего не удаляет. Нажмите «Да, удалить» — вы на списке, контактов на один меньше, по имени его уже не найти.
7. На главной нажмите «Пора связаться» в шапке. Пока частота не задана ни одному контакту, там подсказка, как её задать.
8. Откройте тестовый контакт, у которого последняя заметка старше месяца. Нажмите «Редактировать», в поле «Как часто общаться» выберите «Раз в месяц», нажмите «Сохранить» — в карточке строка «Как часто общаться: Раз в месяц».
9. Вернитесь на главную — рядом с «Пора связаться» появилось число. Откройте страницу: этот человек там, с датой последней заметки и надписью «просрочено на N дней».
10. Нажмите на него, напишите заметку и нажмите «Назад» в браузере — на «Пора связаться» его больше нет, число в шапке главной уменьшилось.
11. Добавьте новый контакт с частотой «Раз в неделю» — на «Пора связаться» его нет: срок для него только начался.

Страницы списка проверяются на тестовых данных (`pnpm db:seed`), где контактов больше 50:

12. На главной над списком и под ним переключатель «‹ Назад 1 2 3 4 5 … 20 Вперёд ›». Нажмите «2» — открылась 2-я страница, подпись «Показаны 51–100 из N», в адресе `?page=2`.
13. Скопируйте адрес и откройте его в другом браузере — там та же 2-я страница с теми же людьми. В первом браузере нажмите «Назад» — снова 1-я страница.
14. Введите в поиск «ан» — подпись «Найдено: … · показаны 1–50», переключатель листает найденных. Нажмите крестик в поиске — снова 1-я страница всех контактов.
15. Перейдите на 5-ю страницу, откройте любой контакт и нажмите «Все контакты» — снова 5-я страница.

Группы:

16. На главной нажмите «Группы» в шапке. Пока групп нет, там поле «Новая группа» и подсказка «Пока нет ни одной группы».
17. Введите «Теннис» и нажмите «Создать» (или Enter) — группа появилась в списке с надписью «пока никого», поле очистилось. Создайте ещё «аналитики» — она встала выше «Теннис»: группы идут по алфавиту без учёта регистра.
18. Введите «теннис» и нажмите «Создать» — под полем «Группа «Теннис» уже есть». Нажмите «Создать» с пустым полем — «Укажите название группы».
19. У «Теннис» нажмите «Переименовать», впишите «Теннис по средам», «Сохранить» — название сменилось. «Переименовать», изменить текст и «Отмена» — название прежнее.
20. У «аналитики» нажмите «Удалить» — на месте строки вопрос «Удалить группу «аналитики»? Люди из неё останутся в контактах, только без этой группы.». «Отмена» ничего не удаляет, «Да, удалить» убирает группу.
21. Откройте карточку любого контакта: первая строка — «Группы», в ней только кнопка «+ группа». Нажмите её, выберите «Теннис по средам» — окошко закрылось, появилась метка. Нажмите «+ группа» снова: «Теннис по средам» в списке уже нет.
22. В окошке введите «Йога» и нажмите «Создать» — у человека метка «Йога», а на странице «Группы» есть «Йога — 1 контакт». Нажмите крестик у «Йога» — метка исчезла, группа на странице «Группы» осталась с надписью «пока никого».
23. Нажмите «+ группа» и Escape — окошко закрывается, ничего не меняется. Нажмите «Создать» с пустым полем — окошко остаётся, под полем «Укажите название группы».
24. На главной под поиском появился ряд меток «Все», «аналитики», «Теннис по средам», «Йога» (по алфавиту), выделена «Все». Нажмите «Теннис по средам» — в списке только её люди, подпись «В группе: N контактов», в адресе `?group=…`. Введите в поиск имя — ищется только среди людей группы. Нажмите «Все» — снова весь список.
25. Выберите группу, где никого нет (например, «Йога»): видно «В группе «Йога» пока никого» и кнопку «Показать все контакты». В группе введите в поиск имя, которого там нет — «Никого не нашлось» и кнопка «Показать всех в группе».
26. Выберите группу, откройте любой контакт, нажмите «Все контакты» — вернулись в ту же группу. Название «Личная CRM» в шапке всегда ведёт на весь список.
27. В строках списка на главной под именем у людей из групп видны метки групп; у остальных строка такая же, как раньше. Если групп у человека много, лишнее обрезается в конце, строка не растёт.
28. Задайте человеку из группы частоту «Раз в неделю» и подвиньте срок (например, на тестовых данных возьмите контакт со старой заметкой): на «Пора связаться» у него после частоты и даты последней заметки те же метки.

## Как устроено

- **Next.js (App Router), TypeScript** — страницы и серверный код в `src/app`
- **Tailwind CSS и shadcn/ui** — интерфейс; готовые компоненты лежат в `src/components/ui`
- **PostgreSQL в Docker** — описан в `compose.yaml`, слушает порт 5433
- **Drizzle** — схема таблиц в `src/db/schema.ts`, миграции в папке `drizzle`

К базе обращается только сервер: браузер получает готовые страницы и отправляет формы. Список и карточки читаются из базы при каждом открытии, без кеша, поэтому в любом браузере видны одни и те же актуальные данные.

Порты выбраны так, чтобы не мешать другим проектам на этом компьютере: приложение — 3001, база — 5433.

Приложение и база доступны только с этого компьютера (адрес `127.0.0.1`). Входа по паролю в приложении нет, поэтому в домашнюю или публичную сеть оно не выставлено: с телефона или другого компьютера его не открыть. Это задаётся параметром `-H 127.0.0.1` в командах `dev` и `start` в `package.json`.

Next.js умеет отправлять своим разработчикам анонимную статистику использования. Здесь она отключена: в командах `package.json` стоит `NEXT_TELEMETRY_DISABLED=1`.

## Выкатка на сервер

Приложение живёт на сервере по адресу <https://app.therooks.ru>. Новая версия выкатывается сама.

### Как выкатить новую версию

Отправьте изменения в ветку `main` (`git push`). Дальше всё происходит само, примерно 3–5 минут:

1. GitHub Actions собирает образ приложения и кладёт его в GHCR (хранилище образов GitHub) с тегом — номером коммита.
2. Копирует на сервер скрипты из папки `deploy/` и запускает `deploy.sh`.
3. На сервере: скачивается новый образ → отдельный одноразовый контейнер применяет миграции базы → только после этого запускается новая версия → проверка `/health`.
4. Старые образы удаляются: на диске остаются текущий и предыдущий.

Если миграции упали, новая версия не стартует, а прежняя продолжает работать.

### Как проверить, что выкатилось

- Откройте <https://app.therooks.ru/health>. Должно быть `{"status":"ok","version":"…"}`, где `version` — номер вашего коммита (`git rev-parse HEAD`). Если базы нет или она не отвечает, ответ будет с ошибкой 503.
- Ход выкатки виден на вкладке Actions репозитория; зелёная галочка — всё прошло.

### Если выкатка красная

Автоматического отката нет, это сделано специально: сервер сам ничего не откатывает. В логе шага указано, что именно упало. Чтобы вернуть предыдущую версию, выполните на своём компьютере:

```bash
ssh crm '~/crm/deploy.sh "$(cat ~/crm/state/previous)"'
```

Миграции базы только добавляются вперёд и назад не откатываются, поэтому после отката база остаётся новой структуры.

Логи приложения на сервере: `ssh crm 'docker logs --tail 50 prod-app-1'`.

Если сборка в Actions падает с `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`, значит, в `pnpm-lock.yaml` попал пакет, вышедший меньше суток назад: pnpm такие не ставит ради безопасности. Подождите сутки и перезапустите выкатку (вкладка Actions → Re-run jobs); правила pnpm при этом не меняйте.

### Что настроено на сервере и в GitHub

- **Сервер:** папка `~/crm` пользователя `crmapp` (скрипты из `deploy/`, файл `.env`, папка `state` с записью о текущем и предыдущем образе). Docker compose, проект `prod`: база PostgreSQL (своя, в Docker, порт наружу не открыт) и приложение на `127.0.0.1:3001`. Снаружи его показывает nginx по https; конфиг сайта лежит в `deploy/nginx/` и ставится выкаткой.
- **Файл `~/crm/.env` на сервере** создаётся один раз вручную и в git не попадает. В нём три строки: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`. Пароль можно сгенерировать прямо на сервере, не показывая его на экране:

  ```bash
  ssh crm 'set -e; mkdir -p ~/crm; cd ~/crm; [ ! -e .env ] || { echo ".env уже есть"; exit 1; }; umask 077; printf "POSTGRES_USER=crm\nPOSTGRES_DB=crm\nPOSTGRES_PASSWORD=%s\n" "$(openssl rand -hex 24)" > .env; ls -l .env'
  ```

- **GitHub, Settings → Secrets and variables → Actions:** секрет `DEPLOY_SSH_KEY` (приватный ключ, которым выкатка заходит на сервер) и переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` (адрес, пользователь и отпечаток сервера). Публичная часть ключа добавлена в `~/.ssh/authorized_keys` пользователя `crmapp`.

### Тестовые данные на сервере

Один раз, на пустой базе (на непустой команда ничего не сделает и сообщит об этом):

```bash
ssh crm '~/crm/seed.sh'
```

## Если что-то не работает

- **«Не удалось загрузить данные»** — не запущена база. Запустите Docker Desktop и выполните `docker compose up -d`.
- **`DATABASE_URL is not set`** — нет файла `.env` или в нём не заполнена строка подключения.
- **Порт 3001 занят** — приложение уже запущено в другом окне терминала. Закройте его или остановите там же через `Ctrl+C`.
