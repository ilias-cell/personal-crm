# Личная CRM

Приложение для ведения контактов людей, которых знаешь лично: кто это, откуда знакомы, телефон, почта и заметки после разговоров. Идея и границы продукта — в `specs/01-продуктовая-идея.md`.

## Что умеет

- Вход по ссылке из письма, без пароля: вводите почту, получаете письмо с кнопкой «Войти», открываете ссылку. Первый вход и есть регистрация: имя не спрашивается. Без входа приложение не открывается
- Ссылка работает один раз и 15 минут; новая ссылка отменяет прежние. Писем не больше 3 на одну почту за 10 минут и не больше 10 за час с одного адреса в интернете. Почта без пробелов по краям и без различия больших и маленьких букв
- Вход держится 30 дней с последнего захода на этом устройстве, можно сидеть с нескольких устройств сразу. В шапке — ваша почта и «Выйти» (выход только на этом устройстве)
- Свои данные: у каждого контакта и каждой группы есть владелец, заметки принадлежат владельцу контакта. Пользователь видит и меняет только своё; чужой контакт по прямой ссылке выглядит как несуществующий. У каждого свои группы: у двоих может быть по группе «Друзья». Новый пользователь начинает с пустого списка
- Список контактов по 50 на странице, новые сверху. Переключатель страниц — над списком и под ним, номер страницы виден в адресе: ссылку на страницу можно открыть в другом браузере
- Поиск по имени среди всех контактов: без учёта регистра, «е» и «ё» считаются одной буквой, слова можно вводить в любом порядке. Если найдено больше 50, найденные тоже делятся на страницы
- «Все контакты» в карточке, на «Добавить контакт» и на «Пора связаться» возвращает на ту страницу списка и с тем поиском, откуда вы пришли
- Добавление контакта: имя (обязательно), кто это, откуда знакомы, телефон, почта, как часто общаться
- Карточка контакта с лентой заметок: каждая заметка сохраняется с датой, новые сверху
- Редактирование контакта
- Удаление контакта: кнопка внизу страницы редактирования, с вопросом «Точно удалить?». Контакт удаляется вместе со всеми заметками и безвозвратно: корзины нет
- «Как часто общаться»: в форме контакта можно выбрать «Раз в неделю», «Раз в месяц», «Раз в квартал», «Раз в год» или оставить «Не задано». Выбранная частота видна в карточке
- Страница «Пора связаться»: люди, с которыми вы не общались дольше выбранного срока, самые просроченные сверху. Ссылка на неё — в шапке главной, рядом число таких людей

- Страница «Группы» (ссылка в шапке главной): свои группы, например «Семья», «Друзья», «Теннис». Группы идут по алфавиту, у каждой видно число контактов. Группу можно создать, переименовать и удалить; при удалении люди остаются в контактах, только без этой группы. Нажатие на название группы открывает главную с людьми этой группы
- Выбор группы на главной: под поиском ряд меток «Все» и группы. Выбрали группу — в списке только её люди; поиск, страницы и подпись работают внутри группы («В группе: 12 контактов»), а сама группа сохраняется в адресе. Группу, которой нет, адрес не ломает: показываются все контакты
- Группы человека видны маленькими метками в строке списка на главной (перед «кто это · откуда знакомы») и на странице «Пора связаться» (после частоты и даты последней заметки)
- Группы в карточке контакта: первая строка «Группы» — метки с крестиком и кнопка «+ группа». Крестик сразу убирает человека из группы (сама группа остаётся). В «+ группа» можно выбрать готовую группу или вписать название: новое создаёт группу, существующее (в любом регистре) просто добавляет человека в неё

Отдельные заметки удалить нельзя — это сознательное решение.

### Как считается «Пора связаться»

- Общение — это заметка в карточке. Срок считается от последней заметки, каждая новая заметка начинает его заново
- Если заметок нет — от дня, когда задали частоту. Новый контакт с частотой — от дня добавления
- Если частоту поменяли на другую — заново от дня смены. Сохранение формы без смены частоты срок не трогает
- Неделя — 7 дней; месяц, квартал и год — по календарю: от 15 января до 15 февраля, 15 апреля и 15 января следующего года. От 31 января месяц заканчивается в последний день февраля
- Человек появляется на странице в день, когда срок наступил, с надписью «пора сегодня»; дальше — «просрочено на N дней»
- Дни считаются по московскому времени

## Что нужно на компьютере

- [Node.js](https://nodejs.org) 20.12 или новее
- [pnpm](https://pnpm.io)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работают база данных и почтовая заглушка Mailpit (письма для входа на вашем компьютере падают в неё и никуда не уходят)

## Первый запуск

1. Создайте файл с настройками и заполните в нём значения:

   ```bash
   cp .env.example .env
   ```

   Имена переменных уже есть в `.env.example`. Пароль придумайте любой, порт базы — `5433`. `DATABASE_URL` — это строка подключения целиком: `postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@localhost:5433/ИМЯ_БАЗЫ`.

   Для входа добавьте ещё пять строк:

   | Строка | Что писать |
   | --- | --- |
   | `OWNER_EMAIL` | Ваша почта. Контакты, которые уже есть в базе, достанутся пользователю с этой почтой; она нужна `pnpm db:migrate` и `pnpm db:seed` |
   | `BETTER_AUTH_SECRET` | Длинная случайная строка, её подписываются cookie входа. Получить: `openssl rand -base64 32` |
   | `BETTER_AUTH_URL` | `http://127.0.0.1:3001` — адрес приложения, из него строятся ссылки в письмах |
   | `SMTP_URL` | `smtp://127.0.0.1:1025` — почтовая заглушка Mailpit |
   | `MAIL_FROM` | От кого письма, на компьютере подойдёт любое: `Личная CRM <noreply@example.com>` |

2. Запустите базу данных и почтовую заглушку:

   ```bash
   docker compose up -d
   ```

3. Установите зависимости и создайте таблицы:

   ```bash
   pnpm install
   pnpm db:migrate
   ```

   Если в базе уже есть контакты (с прошлых версий), `pnpm db:migrate` отдаст их пользователю с почтой из `OWNER_EMAIL`. Без этой строки он остановится с ошибкой «OWNER_EMAIL is not set» и ничего не изменит.

4. Запустите приложение:

   ```bash
   pnpm dev
   ```

5. Откройте в браузере <http://127.0.0.1:3001> (именно этот адрес, как в `BETTER_AUTH_URL`: вход привязан к адресу). Вы увидите страницу входа.

6. Войдите. Введите почту и нажмите «Получить ссылку». Письма видны в Mailpit: <http://127.0.0.1:8025>. Откройте письмо и нажмите «Войти». Чтобы увидеть свои прежние контакты, вводите почту из `OWNER_EMAIL`. Любая другая почта (например, `friend@example.com`) — это другой пользователь с пустым списком; настоящих ящиков для этого не нужно.

## Обычный запуск

Когда всё уже настроено, достаточно двух команд:

```bash
docker compose up -d
pnpm dev
```

Приложение — <http://127.0.0.1:3001>, письма для входа — в Mailpit на <http://127.0.0.1:8025>.

Остановить приложение — `Ctrl+C` в терминале. Остановить базу и Mailpit — `docker compose stop` (данные базы сохраняются, письма в Mailpit пропадают).

`pnpm dev` — режим разработки: удобен, пока приложение меняется, но страницы открываются медленнее. Чтобы пользоваться приложением на полной скорости:

```bash
pnpm build
pnpm start
```

После изменений в коде `pnpm build` нужно выполнить заново.

## Тестовые данные

```bash
pnpm db:seed
```

Команда добавляет 1000 выдуманных контактов и заметки к ним. Они достаются владельцу: пользователю с почтой из `OWNER_EMAIL` (его команда находит или создаёт сама). Войдите под этой почтой — контакты ваши; другой пользователь их не увидит. Без `OWNER_EMAIL` команда остановится с понятной ошибкой. Она работает только на пустой базе: если в базе уже есть хотя бы один контакт, команда ничего не меняет и сообщает об этом. Телефоны начинаются с несуществующего кода `000`, почта — на домене `example.com`, так что случайно позвонить или написать реальному человеку не получится.

## Тесты

```bash
docker compose up -d
pnpm test
```

Нужны запущенные база и Mailpit (оба поднимает `docker compose up -d`) и Node.js 22.12 или новее. Тесты проходят настоящий вход: просят ссылку, берут её из Mailpit и открывают. Ящик Mailpit они не очищают, каждый тест входит под своей почтой вида `что-то-1a2b3c4d@example.com`. Тесты работают в отдельной базе рядом с рабочей — её имя то же, но с `_test` на конце (например, `personal_crm_test`). Они сами создают эту базу и обновляют в ней таблицы, а ваши контакты не трогают. Если база не запущена, тесты сразу скажут: «Start it with `docker compose up -d`».

### Сквозные тесты (e2e)

Настоящий браузер проходит сценарии так же, как человек: входит по ссылке из письма (письма берёт из Mailpit, он должен быть запущен), открывает список, добавляет контакт, находит его поиском, пишет заметку, обновляет страницу и открывает тот же адрес в другом окне без общих данных.

Один раз после установки зависимостей скачайте браузер для тестов:

```bash
pnpm exec playwright install chromium
```

Запуск:

```bash
docker compose up -d
pnpm test:e2e
```

Команда сама собирает приложение (около минуты) и запускает его на порту 3002 со своей базой — имя с `_e2e` на конце (например, `personal_crm_e2e`). Перед каждым тестом эта база очищается; рабочая база и запущенный `pnpm dev` не затрагиваются. Если тест упал, отчёт со скриншотом и записью шагов откроет `pnpm exec playwright show-report`.

## Как проверить руками

1. Откройте <http://127.0.0.1:3001> и войдите (шаги — в разделе «Вход и свои данные» ниже). Виден список контактов, над ним подпись: «Всего: N контактов» или, если контактов больше 50, «Показаны 1–50 из N».
2. Нажмите «Добавить контакт», заполните имя, нажмите «Добавить контакт» — новый контакт появился первым в списке.
3. Введите его имя в поиск — список сузился до него. Откройте карточку.
4. Напишите заметку, нажмите «Сохранить заметку» — она появилась в ленте с датой. Обновите страницу — заметка на месте.
5. Откройте тот же адрес в другом браузере — там те же контакты и та же заметка.
6. Откройте карточку контакта (лучше тестового), нажмите «Редактировать», внизу страницы — «Удалить контакт». Появится вопрос с именем и числом заметок; «Отмена» ничего не удаляет. Нажмите «Да, удалить» — вы на списке, контактов на один меньше, по имени его уже не найти.
7. На главной нажмите «Пора связаться» в шапке. Пока частота не задана ни одному контакту, там подсказка, как её задать.
8. Откройте тестовый контакт, у которого последняя заметка старше месяца. Нажмите «Редактировать», в поле «Как часто общаться» выберите «Раз в месяц», нажмите «Сохранить» — в карточке строка «Как часто общаться: Раз в месяц».
9. Вернитесь на главную — рядом с «Пора связаться» появилось число. Откройте страницу: этот человек там, с датой последней заметки и надписью «просрочено на N дней».
10. Нажмите на него, напишите заметку и нажмите «Назад» в браузере — на «Пора связаться» его больше нет, число в шапке главной уменьшилось.
11. Добавьте новый контакт с частотой «Раз в неделю» — на «Пора связаться» его нет: срок для него только начался.

Страницы списка проверяются на тестовых данных (`pnpm db:seed`), где контактов больше 50:

12. На главной над списком и под ним переключатель «‹ Назад 1 2 3 4 5 … 20 Вперёд ›». Нажмите «2» — открылась 2-я страница, подпись «Показаны 51–100 из N», в адресе `?page=2`.
13. Скопируйте адрес и откройте его в другом браузере — там та же 2-я страница с теми же людьми. В первом браузере нажмите «Назад» — снова 1-я страница.
14. Введите в поиск «ан» — подпись «Найдено: … · показаны 1–50», переключатель листает найденных. Нажмите крестик в поиске — снова 1-я страница всех контактов.
15. Перейдите на 5-ю страницу, откройте любой контакт и нажмите «Все контакты» — снова 5-я страница.

Группы:

16. На главной нажмите «Группы» в шапке. Пока групп нет, там поле «Новая группа» и подсказка «Пока нет ни одной группы».
17. Введите «Теннис» и нажмите «Создать» (или Enter) — группа появилась в списке с надписью «пока никого», поле очистилось. Создайте ещё «аналитики» — она встала выше «Теннис»: группы идут по алфавиту без учёта регистра.
18. Введите «теннис» и нажмите «Создать» — под полем «Группа «Теннис» уже есть». Нажмите «Создать» с пустым полем — «Укажите название группы».
19. У «Теннис» нажмите «Переименовать», впишите «Теннис по средам», «Сохранить» — название сменилось. «Переименовать», изменить текст и «Отмена» — название прежнее.
20. У «аналитики» нажмите «Удалить» — на месте строки вопрос «Удалить группу «аналитики»? Люди из неё останутся в контактах, только без этой группы.». «Отмена» ничего не удаляет, «Да, удалить» убирает группу.
21. Откройте карточку любого контакта: первая строка — «Группы», в ней только кнопка «+ группа». Нажмите её, выберите «Теннис по средам» — окошко закрылось, появилась метка. Нажмите «+ группа» снова: «Теннис по средам» в списке уже нет.
22. В окошке введите «Йога» и нажмите «Создать» — у человека метка «Йога», а на странице «Группы» есть «Йога — 1 контакт». Нажмите крестик у «Йога» — метка исчезла, группа на странице «Группы» осталась с надписью «пока никого».
23. Нажмите «+ группа» и Escape — окошко закрывается, ничего не меняется. Нажмите «Создать» с пустым полем — окошко остаётся, под полем «Укажите название группы».
24. На главной под поиском появился ряд меток «Все», «аналитики», «Теннис по средам», «Йога» (по алфавиту), выделена «Все». Нажмите «Теннис по средам» — в списке только её люди, подпись «В группе: N контактов», в адресе `?group=…`. Введите в поиск имя — ищется только среди людей группы. Нажмите «Все» — снова весь список.
25. Выберите группу, где никого нет (например, «Йога»): видно «В группе «Йога» пока никого» и кнопку «Показать все контакты». В группе введите в поиск имя, которого там нет — «Никого не нашлось» и кнопка «Показать всех в группе».
26. Выберите группу, откройте любой контакт, нажмите «Все контакты» — вернулись в ту же группу. Название «Личная CRM» в шапке всегда ведёт на весь список.
27. В строках списка на главной под именем у людей из групп видны метки групп; у остальных строка такая же, как раньше. Если групп у человека много, лишнее обрезается в конце, строка не растёт.
28. Задайте человеку из группы частоту «Раз в неделю» и подвиньте срок (например, на тестовых данных возьмите контакт со старой заметкой): на «Пора связаться» у него после частоты и даты последней заметки те же метки.

Вход и свои данные:

29. Выйдите (кнопка «Выйти» в шапке) и откройте <http://127.0.0.1:3001> — страница «Вход»: поле «Почта» и кнопка «Получить ссылку», в шапке только «Личная CRM». Откройте <http://127.0.0.1:3001/groups> — тоже страница входа. <http://127.0.0.1:3001/health> открывается и без входа.
30. Введите «  Anna@Example.COM  » с пробелами и большими буквами, нажмите «Получить ссылку» — «Ссылка для входа отправлена на anna@example.com». В Mailpit (<http://127.0.0.1:8025>) письмо «Вход в Личную CRM» от «Личная CRM», на anna@example.com, с кнопкой «Войти», строками «Ссылка работает 15 минут.» и «Если вы не запрашивали вход — просто проигнорируйте письмо». Нажмите «Войти» — вы внутри, список пустой («Пока нет ни одного контакта»), в шапке «anna@example.com» и «Выйти».
31. Введите «anna@», «anna» и пустое поле — каждый раз под полем «Проверьте адрес почты», введённый текст остаётся, письма не приходят.
32. Откройте ту же ссылку из письма ещё раз после выхода — «Ссылка устарела, запросите новую» и кнопка «Запросить новую ссылку», она ведёт на страницу входа. Запросите две ссылки подряд на одну почту и откройте первую — тоже «Ссылка устарела»; вторая впускает.
33. Запросите ссылку на одну почту четыре раза подряд — на четвёртый «Слишком часто, попробуйте через несколько минут», четвёртого письма в Mailpit нет. Другая почта при этом работает.
34. Ваши данные и чужие: войдите под `OWNER_EMAIL` в одном браузере и под `friend@example.com` в другом (например, в окне инкогнито). У `friend@example.com` пустой список и пустая страница «Группы». Добавьте у него контакт «Вера Климова» — в вашем браузере её нет ни в списке, ни в поиске. Скопируйте адрес её карточки и откройте в своём браузере — «Здесь ничего нет», во вкладке «Контакт не найден». Создайте у него группу «Друзья», а у себя такую же — обе создаются.
35. Нажмите «Выйти» в одном браузере — в другом вы остаётесь внутри.
36. Сузьте окно до ширины телефона (375 px): «Личная CRM», почта и «Выйти» помещаются в шапке, длинная почта обрезается многоточием.

## Как устроено

- **Next.js (App Router), TypeScript** — страницы и серверный код в `src/app`
- **Tailwind CSS и shadcn/ui** — интерфейс; готовые компоненты лежат в `src/components/ui`
- **PostgreSQL в Docker** — описан в `compose.yaml`, слушает порт 5433
- **Drizzle** — схема таблиц в `src/db/schema.ts`, миграции в папке `drizzle`
- **Better Auth** — вход по ссылке из письма; настройка в `src/lib/auth.ts`. Проверки при запросе ссылки (почта, лимиты, отмена прежних ссылок) — в одном месте и работают и для формы, и для прямого запроса к серверу
- **Nodemailer** — отправка писем по адресу из `SMTP_URL`: на компьютере и в тестах это Mailpit, на сервере Resend. Код один и тот же, различаются только настройки
- **Mailpit в Docker** — почтовая заглушка, описана в `compose.yaml`: SMTP на порту 1025, страница с письмами на порту 8025

К базе обращается только сервер: браузер получает готовые страницы и отправляет формы. Список и карточки читаются из базы при каждом открытии, без кеша, поэтому в любом браузере, где вошли под той же почтой, видны одни и те же актуальные данные. Каждый запрос к данным идёт с владельцем: чужие контакты, заметки и группы не отдаются ни страницам, ни серверным действиям.

Порты выбраны так, чтобы не мешать другим проектам на этом компьютере: приложение — 3001, база — 5433, Mailpit — 1025 и 8025.

Приложение, база и Mailpit на этом компьютере доступны только с него самого (адрес `127.0.0.1`): в домашнюю сеть они не выставлены, с телефона или другого компьютера их не открыть. Для приложения это задаётся параметром `-H 127.0.0.1` в командах `dev` и `start` в `package.json`. Вход по ссылке защищает приложение на сервере; на вашем компьютере он нужен, чтобы проверять приложение так же, как оно работает у всех.

Next.js умеет отправлять своим разработчикам анонимную статистику использования. Здесь она отключена: в командах `package.json` стоит `NEXT_TELEMETRY_DISABLED=1`.

## Выкатка на сервер

Приложение живёт на сервере по адресу <https://app.therooks.ru>. Новая версия выкатывается сама.

### Как выкатить новую версию

Отправьте изменения в ветку `main` (`git push`). Дальше всё происходит само, примерно 3–5 минут:

1. GitHub Actions собирает образ приложения и кладёт его в GHCR (хранилище образов GitHub) с тегом — номером коммита.
2. Копирует на сервер скрипты из папки `deploy/` и запускает `deploy.sh`.
3. На сервере: снимается бэкап базы → скачивается новый образ → отдельный одноразовый контейнер применяет миграции базы → только после этого запускается новая версия → проверка `/health`.
4. Старые образы удаляются: на диске остаются текущий и предыдущий. Из бэкапов выкатки остаются 10 последних.

Если бэкап не снялся, выкатка останавливается сразу и ничего не меняет. Если миграции упали, новая версия не стартует, а прежняя продолжает работать.

### Как проверить, что выкатилось

- Откройте <https://app.therooks.ru/health>. Должно быть `{"status":"ok","version":"…"}`, где `version` — номер вашего коммита (`git rev-parse HEAD`). Если базы нет или она не отвечает, ответ будет с ошибкой 503.
- Ход выкатки виден на вкладке Actions репозитория; зелёная галочка — всё прошло.

### Если выкатка красная

Автоматического отката нет, это сделано специально: сервер сам ничего не откатывает. В логе шага указано, что именно упало. Чтобы вернуть предыдущую версию, выполните на своём компьютере:

```bash
ssh crm '~/crm/deploy.sh "$(cat ~/crm/state/previous)"'
```

Миграции базы только добавляются вперёд и назад не откатываются, поэтому после отката база остаётся новой структуры.

Если новая версия испортила данные, базу можно вернуть из бэкапа, снятого перед выкаткой, — см. «Бэкапы и восстановление».

Логи приложения на сервере: `ssh crm 'docker logs --tail 50 prod-app-1'`.

Если сборка в Actions падает с `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`, значит, в `pnpm-lock.yaml` попал пакет, вышедший меньше суток назад: pnpm такие не ставит ради безопасности. Подождите сутки и перезапустите выкатку (вкладка Actions → Re-run jobs); правила pnpm при этом не меняйте.

### Что настроено на сервере и в GitHub

- **Сервер:** папка `~/crm` пользователя `crmapp` (скрипты из `deploy/`, файл `.env`, папка `state` с записью о текущем и предыдущем образе, папка `backups` с бэкапами базы). Docker compose, проект `prod`: база PostgreSQL (своя, в Docker, порт наружу не открыт) и приложение на `127.0.0.1:3001`. Снаружи его показывает nginx по https; конфиг сайта лежит в `deploy/nginx/` и ставится выкаткой.
- **Файл `~/crm/.env` на сервере** создаётся один раз вручную и в git не попадает. В нём три строки базы: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — и пять строк входа (см. «Настройка входа на сервере»). Если какой-то строки нет, `deploy.sh` останавливается сразу, до бэкапа, и называет недостающие строки (значения он не показывает). Пароль базы можно сгенерировать прямо на сервере, не показывая его на экране:

  ```bash
  ssh crm 'set -e; mkdir -p ~/crm; cd ~/crm; [ ! -e .env ] || { echo ".env уже есть"; exit 1; }; umask 077; printf "POSTGRES_USER=crm\nPOSTGRES_DB=crm\nPOSTGRES_PASSWORD=%s\n" "$(openssl rand -hex 24)" > .env; ls -l .env'
  ```

- **GitHub, Settings → Secrets and variables → Actions:** секрет `DEPLOY_SSH_KEY` (приватный ключ, которым выкатка заходит на сервер) и переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` (адрес, пользователь и отпечаток сервера). Публичная часть ключа добавлена в `~/.ssh/authorized_keys` пользователя `crmapp`.

### Настройка входа на сервере

Делается один раз, до первой выкатки со входом. Пока этого нет, выкатка остановится на проверке `.env`.

**1. Resend** — сервис, через который сервер отправляет письма со ссылкой для входа.

1. Создайте аккаунт на <https://resend.com>.
2. Domains → Add Domain → `mail.therooks.ru`. Письма идут с поддомена `mail`, а не с основного `therooks.ru`: так советует сам Resend, и репутация основного домена не страдает.
3. Resend покажет записи DNS (MX, SPF и DKIM). Добавьте их в DNS домена `therooks.ru` у регистратора — это делаете вы, агент DNS не трогает. Дождитесь статуса «Verified».
4. API Keys → Create API Key: право «Sending access» (только отправка) и домен `mail.therooks.ru`. Ключ показывается один раз — скопируйте.

**2. Строки в `~/crm/.env` на сервере.** Файл уже есть (три строки базы); команды дописывают в него строки, ничего не стирая и не показывая секреты.

Не секретные строки (вместо `ВАША_ПОЧТА` — почта, на которую достанутся все прежние контакты; это должна быть та, под которой вы будете входить):

```bash
ssh crm 'cd ~/crm && printf "OWNER_EMAIL=%s\nBETTER_AUTH_URL=%s\nMAIL_FROM=%s\n" "ВАША_ПОЧТА" "https://app.therooks.ru" "Личная CRM <noreply@mail.therooks.ru>" >> .env'
```

Секрет для cookie входа — генерируется на сервере и не выводится на экран:

```bash
ssh crm 'cd ~/crm && printf "BETTER_AUTH_SECRET=%s\n" "$(openssl rand -base64 32)" >> .env'
```

Ключ Resend — вводится вслепую (символы не видны на экране и не попадают в историю команд):

```bash
ssh -t crm 'cd ~/crm && read -r -s -p "Ключ Resend: " key && echo && printf "SMTP_URL=smtps://resend:%s@smtp.resend.com:465\n" "$key" >> .env && unset key'
```

Проверка: имена строк (значений команда не показывает) и права файла — должны быть `-rw-------`, читает только владелец:

```bash
ssh crm 'cd ~/crm && cut -d= -f1 .env && ls -l .env'
```

В списке должны быть `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `OWNER_EMAIL`, `BETTER_AUTH_URL`, `MAIL_FROM`, `BETTER_AUTH_SECRET`, `SMTP_URL`. Если команду запустили дважды, в файле будет дубль строки: последняя строка побеждает, но лучше удалить лишнюю вручную.

**Опечатка в `OWNER_EMAIL`** — самая неприятная ошибка: все прежние контакты достанутся пользователю, под которым никто не войдёт, и после выкатки вы увидите пустой список. Поэтому перед merge ещё раз сверьте строку.

### Откат после выкатки входа

Откат — только вручную, запускаете вы. Выкатка входа меняет базу: у контактов и групп появляется владелец, а прежнее приложение с такой базой работать не будет (добавить контакт не получится). Поэтому вернуть нужно и приложение, и базу. Два шага, подряд и именно в этом порядке:

1. **Прошлая версия приложения:**

   ```bash
   ssh crm '~/crm/deploy.sh "$(cat ~/crm/state/previous)"'
   ```

   Прежнее приложение запустится на новой базе: контакты откроются, но добавить новые нельзя — это ожидаемо до шага 2.

2. **База из бэкапа этой выкатки.** Выберите файл `deploy-….dump`, снятый перед выкаткой входа (`ssh crm 'ls -lh ~/crm/backups'`; в конце имени — версия приложения до выкатки), и восстановите:

   ```bash
   ssh -t crm '~/crm/restore.sh ~/crm/backups/ИМЯ_ФАЙЛА.dump'
   ```

   Скрипт сохранит копию текущей базы, заменит базу бэкапом и поднимет ту версию приложения, которая работает сейчас, — после шага 1 это прошлая.

Порядок важен: после загрузки бэкапа `restore.sh` применяет миграции работающей версии. Если к этому моменту работает ещё новая версия, миграция входа сразу вернёт базе новую структуру, и откат не получится.

Всё, что внесли в приложение после выкатки (контакты друзей, новые заметки), пропадёт из рабочей базы и останется только в копии `before-restore-….dump`.

### Бэкапы и восстановление

**Когда снимается бэкап.** Каждая выкатка первым делом снимает бэкап базы прода — до миграций и до запуска новой версии. Ручной откат через `deploy.sh` тоже снимает бэкап.

**Где лежат.** На сервере в папке `~/crm/backups`. Открыть их может только пользователь `crmapp`: в бэкапах личные данные. Посмотреть список:

```bash
ssh crm 'ls -lh ~/crm/backups'
```

**Как читать имя.** `deploy-20261108-093242-d6dd55d….dump`:

- первое слово — откуда бэкап: `deploy` — снят выкаткой, `before-restore` — копия базы, снятая скриптом восстановления перед заменой, `manual` — снят вручную;
- дальше дата и время по UTC (по Москве на 3 часа больше);
- в конце версия приложения, которая работала в тот момент. У бэкапа выкатки это версия **до** выкатки — та, что была на `/health` перед merge.

**Сколько хранятся.** Бэкапов выкатки — 10 последних, более старые удаляются после удачной выкатки. Бэкапы `before-restore` и `manual` сами не удаляются никогда: лишние удаляйте вручную.

**Снять бэкап вручную** (например, перед тем как что-то поменять в данных руками):

```bash
ssh crm '~/crm/backup.sh manual'
```

**Важно:** бэкапы лежат на том же сервере, что и база. От ошибки в данных или в миграции они спасают, а от потери самого сервера — нет.

#### Как восстановить базу из бэкапа

Восстановление запускаете только вы, со своего компьютера. Выберите файл в списке и выполните:

```bash
ssh -t crm '~/crm/restore.sh ~/crm/backups/ИМЯ_ФАЙЛА.dump'
```

Скрипт:

1. Проверяет, что файл читается как бэкап. Если нет — ничего не меняет.
2. Показывает, какой файл восстанавливает, какую базу заменит и какая версия приложения будет поднята. Если бэкап снят при другой версии, чем работает сейчас, — пишет предупреждение.
3. Ждёт, пока вы напечатаете `yes`. Любой другой ответ — выход без изменений.
4. Снимает копию текущей базы (`before-restore-….dump`). Не получилось — выход без изменений.
5. Останавливает приложение, удаляет базу, создаёт её пустой и загружает бэкап.
6. Применяет миграции работающей версии: бэкап выкатки снят до её миграций, без этого новая версия могла бы не открыться.
7. Поднимает приложение той же версии, что работала, и проверяет `/health`. Версию приложения скрипт не меняет.

Пока идёт выкатка, восстановление не запустится, и наоборот: скрипт скажет, что занято, — дождитесь конца и запустите снова.

Изменения, сделанные в приложении после того, как снят бэкап, при восстановлении пропадут. Они остаются в копии `before-restore`.

**Если восстановление упало посередине**, скрипт останавливается и оставляет приложение выключенным, чтобы оно не работало на недовосстановленной базе. В сообщении написано, где лежит копия базы до восстановления; вернуть её можно тем же скриптом:

```bash
ssh -t crm '~/crm/restore.sh ~/crm/backups/before-restore-….dump'
```

### Тестовые данные на сервере

Один раз, на пустой базе (на непустой команда ничего не сделает и сообщит об этом). Контакты достанутся пользователю с почтой из `OWNER_EMAIL` в `.env`:

```bash
ssh crm '~/crm/seed.sh'
```

## Если что-то не работает

- **«Не удалось загрузить данные»** — не запущена база. Запустите Docker Desktop и выполните `docker compose up -d`.
- **`DATABASE_URL is not set`** — нет файла `.env` или в нём не заполнена строка подключения.
- **`OWNER_EMAIL is not set`** при `pnpm db:migrate` или `pnpm db:seed` — в `.env` нет строки `OWNER_EMAIL` (ваша почта). Добавьте её и запустите команду снова: ничего не изменилось.
- **Письмо для входа не приходит** — на компьютере смотрите в Mailpit <http://127.0.0.1:8025> (не в настоящей почте); проверьте, что запущен `docker compose up -d`, а в `.env` стоит `SMTP_URL=smtp://127.0.0.1:1025`.
- **После нажатия «Войти» снова страница входа** — вы открыли приложение по адресу, который отличается от `BETTER_AUTH_URL` (например, `localhost` вместо `127.0.0.1`): вход привязан к адресу. Откройте <http://127.0.0.1:3001>.
- **Порт 3001 занят** — приложение уже запущено в другом окне терминала. Закройте его или остановите там же через `Ctrl+C`.
